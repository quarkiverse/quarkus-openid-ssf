= Quarkus OpenID SSF
:extension-status: experimental

include::./includes/attributes.adoc[]

A Quarkus extension family for the
https://openid.net/specs/openid-sharedsignals-framework-1_0.html[OpenID
Shared Signals Framework (SSF)] and its companion specs
(https://openid.net/specs/openid-caep-1_0-final.html[CAEP],
https://openid.net/specs/openid-risc-1_0-final.html[RISC],
https://www.rfc-editor.org/rfc/rfc9967[RFC 9967 SCIM Events],
https://www.rfc-editor.org/rfc/rfc8417[RFC 8417 Security Event Tokens],
https://www.rfc-editor.org/rfc/rfc8935[RFC 8935 PUSH delivery],
https://www.rfc-editor.org/rfc/rfc8936[RFC 8936 POLL delivery],
https://openid.github.io/sharedsignals/openid-caep-interoperability-profile-1_0.html[CAEP Interoperability Profile 1.0 - draft 02]).

Today the project ships a single extension — the SSF **receiver**.

[[receiver]]
== Receiver

Lets a Quarkus app act as an SSF receiver against any spec-compliant
transmitter, to integrate with public providers like
https://ssf.caep.dev[caep.dev], on-prem / self-hosted IdPs, or custom
implementations.

=== What it does

The protocol work is done by https://github.com/easyssf/easyssf[easyssf]
(`org.easyssf:easyssf-receiver`), a framework independent SSF receiver library
shared with its Spring Boot starter. The extension adds configuration, CDI
wiring, the Vert.x push route, the poll scheduler, the token providers,
Micrometer, a health check, JDBC, the Dev UI and native image support.

* Accepts inbound SETs via **PUSH** (RFC 8935) on a Vert.x route at `/ssf/push`,
  answering with the RFC 8935 error documents; handlers run before the `202`.
* Pulls SETs via **POLL** (RFC 8936) with a poller per transmitter on a virtual
  thread, periodic or long polling, acknowledgements that wait in a store
  (optionally the database) until a request carried them, error reports,
  `Retry-After` handling and a manual `pollNow()`.
* Verifies every SET: JWS signature against the transmitter's JWK Set, `typ`
  header, `iss` / `iat` / `jti` / `aud` / `events` per RFC 8417. RS256-only
  with a 2048-bit minimum RSA key by default (CAEP Interop Profile), tunable.
* Manages the stream of the receiver: `RECEIVER` (default) looks it up at the
  transmitter on startup and creates or updates it, with retries in the
  background; `TRANSMITTER` uses a stream an operator created.
* Receives from several transmitters (`quarkus.openid-ssf.receiver.<name>.*`),
  selected by the issuer of a SET.
* Exposes the stream management API (SSF section 8.1) through
  `SsfReceiverStreamClient` and easyssf's `SsfStreamClient`.
* Optional Micrometer metrics (`easyssf.receiver.*`), a SmallRye Health wellness
  check, JDBC stores over Agroal (processed SETs, pending poll acknowledgements)
  shared by all instances, a Dev UI.
* Outbound auth: static bearer token, OAuth2 `client_credentials` (no extra
  dependency), `quarkus-oidc-client`, or none.

=== Installation

Add the extension to your Quarkus application:

[source,xml,subs=attributes+]
----
<dependency>
    <groupId>io.quarkiverse.openid-ssf</groupId>
    <artifactId>quarkus-openid-ssf-receiver</artifactId>
    <version>{project-version}</version>
</dependency>
----

=== Quick start

The fastest end-to-end smoke test is against the public
https://ssf.caep.dev[caep.dev] transmitter — no Keycloak setup, no
public tunnel, and no admin server of your own.

. Sign in at https://ssf.caep.dev and copy the access token.
. Open https://caep.dev/transmitter/events, set the **audience** and
  start the transmitter session.
. Run the receiver-managed example in POLL mode:
+
[source,shell,subs=attributes+]
----
export SSF_RECEIVER_TRANSMITTER_ACCESS_TOKEN=<your-caep-dev-token>
export SSF_RECEIVER_EXPECTED_AUDIENCE=https://my-receiver.example/ssf

mvn -pl receiver/examples/example-receiver-managed-stream quarkus:dev \
    -Dquarkus.profile=caepdev,poll \
    -Dquarkus.openid-ssf.receiver.poll.interval=5s
----
+
. Fire an event from the caep.dev transmitter tab.
. Inspect `curl -s localhost:28080/events/recent-events | jq`.

See the
https://github.com/quarkiverse/quarkus-openid-ssf#readme[repository README]
for the full walkthrough, and the
https://github.com/quarkiverse/quarkus-openid-ssf/blob/main/receiver/examples/README.md[examples]
for a complete setup with Keycloak as identity provider and transmitter.

=== Consumer SPI

Provide a CDI bean implementing easyssf's `SsfEventHandler`; every handler bean
is invoked for every verified SET, before the transmitter gets its answer:

[source,java]
----
import org.easyssf.receiver.event.SsfEventContext;
import org.easyssf.receiver.event.SsfEventHandler;

@ApplicationScoped
public class MyHandler implements SsfEventHandler {
    @Override
    public void handle(SsfEventContext eventContext) {
        if (eventContext.hasEvent("CaepSessionRevoked")) {
            SsfSubject subject = eventContext.subjectFor("CaepSessionRevoked");
            // … invalidate the session subject.sessionId() of subject.subject() …
        }
    }
}
----

A handler that throws makes the transmitter deliver the SET again, so handlers
have to be idempotent. Without an explicit handler, the default
`LoggingSsfEventHandler` logs `jti` / `iss` / event-type aliases at INFO.

=== Testing

`org.easyssf:easyssf-test` has `TestTransmitter`, an in-process SSF transmitter
and identity provider for the tests of an application: metadata, JWK Set,
signed SETs and access tokens, a token endpoint, the stream API and a poll
endpoint. The examples show a `QuarkusTestResourceLifecycleManager` around it.
